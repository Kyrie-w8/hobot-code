# Prime Agent 与 Crush 设计调研

调研时间：2026-08-09。本文只使用项目官方仓库和官方文档作为依据。

> 本文是设计决策记录，不是当前功能清单或版本路线图。产品行为以 [README](../README.md)、[配置说明](configuration.md)和[变更记录](../CHANGELOG.md)为准。

## 结论

Hobot Code 应继续以 Pi 作为交互运行时，不替换 TUI。Prime Agent 最值得借鉴的是长期任务的
状态模型，Crush 最值得借鉴的是权限、Hook、LSP、Skills 和远程终端体验。两者都不适合被
整体移植到资源受限、经常通过 SSH 使用的 RDK 板端。

## Prime Agent

官方仓库：<https://github.com/PrimeIntellect-ai/prime-agent>

Prime Agent 同样建立在 Pi 之上，其核心增量是独立 supervisor、常驻 session worker、持久
IPython kernel、递归子 Agent、计划任务、持久目标和有界 autonomous mode。它把 TUI 与执行
生命周期分离，因此 SSH 断开后任务仍可运行并重新连接。

值得借鉴：

1. **持久目标**：目标必须由用户显式创建，记录状态、预算、耗时和继续次数，只有质量门通过
   或 Agent 显式完成才算完成。上下文压缩不等于任务完成。
2. **有界自治与质量门**：继续执行受 turn、token、时间预算约束；完成前运行用户定义的验证
   命令，工作区未变化时不重复相同失败检查。
3. **执行与展示分离**：终端只是客户端，worker 持有队列、会话和任务状态，适合不稳定 SSH。
4. **可审计自我完善**：只增量修改补充 Prompt、记忆或 Skill 描述，保留历史和回滚；基础系统
   Prompt 不允许运行时自行重写。
5. **调度语义**：steer、follow-up、定时检查和心跳进入同一会话队列，避免多套并发模型。

不直接采用：

- 持久 IPython 和“所有工具都通过 Python 编程”会增加板端内存、依赖和攻击面。
- 默认递归子 Agent 可能放大模型费用、CPU 占用和并发写冲突。
- 常驻 daemon、worker、kernel 三层进程应作为可选服务，而不是交互 CLI 的启动前提。

## Crush

官方仓库：<https://github.com/charmbracelet/crush>

Crush 是完整 Go TUI Agent，包含多模型、会话、LSP、MCP、Hook、权限规则、标准 Agent Skills、
项目初始化、日志与远程通知。其当前许可证为 FSL-1.1-MIT，因此 Hobot Code 只参考公开设计和
行为，不复制实现源码。

值得借鉴：

1. **声明式权限**：按工具 allow/deny，deny 后工具不进入模型上下文；比仅在调用时询问更清晰。
2. **PreToolUse Hook**：用户可在工具执行前做企业策略、格式化、审计或阻断，带超时和确定输出。
3. **LSP 按需启动**：仅项目与语言匹配时启动，对代码定义、引用和诊断提供结构化上下文。
4. **Agent Skills 标准**：支持用户调用、禁止模型自动调用和多个标准发现路径，便于共享技能。
5. **项目初始化**：扫描项目后生成可审查的 `AGENTS.md`，固化构建命令、约定和验证方式。
6. **SSH 通知**：在终端失焦、需要批准或任务完成时使用 OSC 或 bell，不依赖桌面环境。
7. **可观察日志**：提供 tail/follow 命令，并把 provider、LSP、MCP 调试分层。

不直接采用：

- 不重写 Pi 已成熟的 TUI、会话树、编辑器和 Provider 体系。
- 不默认联网更新 provider catalog；板端发行物必须锁定版本、哈希并支持离线启动。
- 不把 LSP、MCP 或 Hook 进程常驻；它们应按项目启用并受资源上限约束。

## Hobot Code 实施决策

| 阶段 | 能力 | 状态 | 板端边界 |
|---|---|---|---|
| P0 | 声明式权限 | 已采用 | deny 工具不暴露，ask 显示目标与风险，调用阶段再次检查 |
| P0 | 项目初始化与质量门 | 已采用 | 不覆盖现有文件；验证结果绑定工作区指纹 |
| P1 | 分作用域持久记忆 | 已采用 | 有界召回，模型写入默认确认，敏感内容拒绝落库 |
| P1 | 持久目标与预算 | 已采用 | 用户显式创建，预算耗尽暂停，完成受质量门约束 |
| P1 | PreToolUse/PostToolUse Hook | 已采用 | argv 调用、超时、输出上限、脱敏审计，项目 Hook 默认关闭 |
| P1 | SSH OSC/bell 通知 | 已采用 | 仅交互 TUI，默认要求 SSH TTY，本地通知需显式开启 |
| P1 | 资源感知 LSP | 已采用 | 按需启动，默认最多一个进程，不捆绑语言服务器 |
| 扩展 | 临时侧边 Agent | 已采用 | 独立多轮进程、上下文快照、不回写对话、同用户并发受限 |
| P2 | 后台会话与定时检查 | 候选 | 必须可选、零默认常驻，并复用现有权限和会话状态 |
| 暂缓 | 递归子 Agent | 未采用 | 资源、写入隔离、预算与取消模型尚未达到板端要求 |

已经采用的能力都保持在 Pi 扩展边界内，不引入默认常驻 daemon 或递归多 Agent。候选能力只有在资源成本、恢复语义和板端安全模型明确后才进入实现阶段。
